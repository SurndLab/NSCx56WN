# 第六站：Back-End 模組 Part 1

## 介紹

歡迎來到台北南港展覽館！這座現代化的展覽中心以其多功能性及舉辦國際級活動的能力而聞名。本模組中，一些編輯們撰寫了幾篇文章，介紹了台北南港展覽館的相關展覽、活動及設施。每篇文章均以 `.html` 或 `.txt` 格式撰寫，且每篇文章的開頭嵌入了前置資料 (front-matter) 部分，用於提供 meta information。這些文件存儲在名為 `contentpages` 的資料夾（根目錄）中，某些文章的文件可能儲存在子資料夾或嵌套的子資料夾中。

在 `content-pages` 資料夾下，有一個 `images` 資料夾。文章中提到的所有圖片路徑都與該圖片資料夾相關。這表示在嵌套的子資料夾中不會有圖片資料夾，因此當引用任何圖片名稱時，圖片均指向 `content-pages` 資料夾下的 `images` 圖片資料夾。

您需要創建一個網站來展示這些文章。每篇文章將成為一個網頁「頁面」，以下文件中會以「頁面 (page)」來指代這些文章。為了保持目前的文章撰寫工作流程，我們將保持 `content-pages` 資料夾的結構不變。

在本模組中，我們將創建一個網站來列出並載入這些文件和子資料夾。該網站將從 `content-pages` 資料夾中讀取這些靜態文件，並將內容顯示為網頁頁面。頁面 (page) 的命名規則為 `YYYY-MM-DD-title.txt` 或 `YYYY-MM-DD-title.html`。

---

## 項目和任務說明

此模組不需要使用資料庫，所有內容都儲存在 `content-pages` 資料夾或其內的子資料夾中。任何人都可以訪問首頁和展覽活動頁面。當訪問首頁時，應列出所有子資料夾和展覽活動頁面。

**[新增]**：除了現有的文章和資料夾列表，首頁還應包含一個「最新文章」區塊，顯示最近發布的 5 篇文章。這些文章應依照發布日期由新到舊排序，並顯示標題、摘要及發布日期。

## URL 路徑和映射

有關列出子資料夾、展覽活動頁面和標籤查詢的 URL 路由定義。

每個頁面或子資料夾的 URL 定義如下，XX 是您的崗位號碼：

- `/XX_module_c/` 顯示首頁頁面。首頁需列出所有子資料夾和根目錄底下的所有展覽活動頁面。
- `/XX_module_c/events/2025-03-01-example-exhibition` 顯示 `2025-03-01-example-exhibition.html` 或 `2025-03-01-example-exhibition.txt` 的頁面。
- `/XX_module_c/events/sub-folder-name` 列出指定「sub-folder-name」資料夾中的所有子資料夾和展覽活動頁面。
- `/XX_module_c/events/sub-folder-name/2025-03-10-welcome-to-nangang` 顯示「sub-folder-name」資料夾中的 `2025-03-10-welcome-to-nangang.html` 或 `2025-03-10-welcome-to-nangang.txt` 的頁面。
- `/XX_module_c/events/sub-folder-1/sub-folder-2/2025-03-10-welcome-to-nangang` 顯示「sub-folder-1/sub-folder-2/」資料夾中的對應頁面。

標籤查詢的 URL 定義如下：

- `/XX_module_c/tags/tag-name-here` 顯示一個頁面，列出所有包含指定標籤「tag-name-here」的頁面。
- `/XX_module_c/tags` 顯示一個頁面，用於顯示所有標籤的列表頁面。該頁面會列出所有文章中出現過的獨特標籤，並按照字母順序排列。每個標籤都應是可點擊的連結，指向該標籤的查詢頁面。

> **註**：當 `draft` 為 `true` 的情況下，該頁面帶有的標籤 (tags) 不應該被列出在上述的標籤列表頁面及指定標籤頁面裡。

## 文件命名規則

檔案名稱包含日期和標題，格式為 `YYYY-MM-DD-title-in-lower-case-with-hyphens.html` 或 `YYYY-MM-DD-title-in-lower-case-with-hyphens.txt`。

- 檔名的第一部分為 `YYYY-MM-DD` 格式，其中 YYYY 為四位數的年份，MM 為兩位數的月份，DD 為兩位數的日期。
- 檔名的第二部分是檔案的標題，採用 slug 形式。即標題的小寫字母，所有空格均以連字符取代。

範例檔名：

- `2025-03-01-example-exhibition.html`
- `2025-10-20-future-tech-expo.html`
- `2025-01-01-daily-operations-report.txt`

## 內容列表

列出內容時，應顯示標題和摘要。點擊標題或摘要將連結到該展覽活動頁面內容。

- 列表**不應顯示未來的頁面**，即日期在今天之後的頁面。
- 列表也**不應顯示草稿狀態的頁面**，即在檔案的前置資料 (front-matter) 中定義為 `draft: true` 的草稿。
- 列表也應**隱藏沒有定義日期的頁面**。也就是說，當前 11 個字元不是 `YYYY-MM-DD-` 格式時。
- 除了頁面之外，列表還應列出並連結到**子資料夾**。點擊子資料夾名稱時，網站應列出該子資料夾中的內容，即該子資料夾內的頁面和子資料夾。
- 在內容列表中，對於有「精選」屬性 (`featured: true`) 的文章，應在標題旁顯示一個小圖示（例如一個星形圖示）以示區別。

### 內容列表的排序

列表首先列出子資料夾，然後列出內容頁面。子資料夾按**字母順序**排列，內容頁面按**字母逆序**排列。這樣可以使最新的頁面顯示在最上方，而最舊的頁面顯示在最下方。

## 訪問頁面內容

`content-pages` 資料夾中的每個檔案包含一個展覽活動文章頁面的相關內容。每個檔案內容有兩部分：前置資料和主要內容。

前置資料是可選的。如果存在前置資料，它將用 `---` 標記在前置資料部分的開頭和結尾。

**帶有前置資料的 `.html` 檔案範例：**

```html
---
title: This is an Example Page
tags: example, test
cover: example-cover.jpeg
summary: This is a sample summary.
---
<h1>Example Page</h1>
<p>Here is the rest of the content.</p>
<p>And some other paragraph.</p>
<img src="hello-world.jpg" alt="Sample photo">
<footer>That is all</footer>
```

**`.txt` 檔案範例：**

```
---
title: This is another sample page
tags: example, test, plain-text
cover: another-cover.jpeg
summary: This is a sample page in txt format.
---
This is sample main content.
Each line of content is turned into <p></p> paragraph.
sample-image.jpeg
The image path / image name with individual line are turned into <img> tag.

[quote]
This is a blockquote.
It can span multiple lines.
[/quote]

This is footer paragraph.
```

## 前置資料 Front-matter

內容檔案的開頭可能包含前置資料。前置資料 (front-matter) 部分可以定義不同的鍵值對：

| 鍵 | 必填 | 說明 |
|---|---|---|
| `title` | 可選 | 標題 |
| `tags` | 可選 | 標籤，由逗號或逗號加空格分隔 |
| `cover` | 可選 | 封面圖片的路徑 |
| `summary` | 可選 | 摘要，僅限一行，於內容列表列出頁面內容時使用 |
| `draft` | 可選 | 草稿，可以是 `true` 或其他值，任何值不等於 `true` 的都視為 `false` |
| `author` | 可選 | 作者名稱，如果未定義，則預設為「Anonymous author」 |
| `featured` | 可選 | 精選，可以是 `true` 或其他值，用於標記精選文章 |

渲染展覽活動網頁的頁面佈局依序包含以下幾個部分：

1. 封面圖片
2. 標題
3. 主要內容
4. 附註資訊

## 12. 封面圖片

每個展覽活動內容頁的封面圖片路徑預設定義在前置資料 (front-matter) 中。

如果封面圖片未在前置資料中定義，封面圖片將與儲存在 `images` 資料夾中的檔案同名。在這個模組中，我們不需考慮封面圖片缺失的情況。

---

## 13. 標題

封面圖片下方會有一個標題區塊，標題內容的決定依據以下規則。標題應根據以下順序提取：

1. 當前置資料 (front-matter) 定義了 `title` 時，標題區塊的內容使用這個 `title` 的值。
2. 當前置資料中未定義 `title` 時，標題區塊的內容使用第一個 `<h1></h1>` 的文字內容（簡單的文字內容，h1 將不會是 rich HTML）。
3. 當前置資料中無 `title` 且內容中無 `<h1>` 標籤時，標題區塊的內容使用檔案名稱的大寫形式，不包含副檔名及 `YYYY-MM-DD` 日期內容。同時，所有連字符（`-`）應替換為空格。

---

## 14. 主要內容

主要內容應從檔案中動態載入。這裡有一些檔案載入規則：

- 如果副檔名是 `.html`，則主要內容和任何 HTML 標籤會按原樣呈現，無需解析或處理（除了圖片路徑）。它們會直接呈現為 HTML。
- 如果副檔名是 `.txt`，則內容僅有兩種類型：文字行和包含圖片路徑的單獨行。
  - 每行文字會轉換為 HTML 段落。
  - 圖片路徑行會轉換為圖片標籤，這些行沒有任何空格且以 `.jpg` 結尾。
- 無論是 `.html` 還是 `.txt` 檔案，圖片路徑都應替換為適用於伺服器的最終圖片路徑。
- 內容區域中的照片應設為**全寬**，點擊照片時照片會放大。點擊放大的照片會關閉放大視窗並恢復原來的內容，捲動時也會關閉放大照片並返回內容。
- 第一段的首字母應使用**下沉樣式 (drop cap)**，佔據三行。
- **[新增]**：對於 `.txt` 檔案，如果遇到 `[quote]` 和 `[/quote]` 標籤包圍的文字，應將其渲染為一個特殊的引用區塊（例如使用 `<blockquote>` 標籤），並施加不同的樣式以區別於普通段落。
- **[新增]**：在文章內容結束後，應新增一個「相關文章」區塊，顯示與當前文章共享至少一個標籤的 3 篇其他文章。這些相關文章應隨機選擇，並顯示其標題和摘要。如果少於 3 篇，則顯示所有符合條件的文章。

## 15. 附註資訊

附註資訊包含以下資訊：日期、標籤、草稿狀態（如果草稿狀態為 true）。

當往下捲動頁面時，附註資訊區塊會**固定在頂部**。

- **[新增]**：點擊附註資訊的標籤時，能夠連接到標籤查詢 URL。
- **[新增]**：除了現有資訊，附註資訊還應顯示**作者名稱**。如果文章有「精選」屬性 (`featured: true`)，則在附註資訊的頂部顯示一個「精選文章」的標示。

## 標籤

內容頁可以根據標籤 (tags) 進行篩選。標籤查詢的 URL 定義如下：

- `https://webXX.web.tw/XX_module_c/tags` 顯示一個頁面，列出所有出現過的標籤的頁面。
- `https://webXX.web.tw/XX_module_c/tags/tag-name-here` 顯示一個頁面，列出所有包含指定標籤「tag-name-here」的頁面。

## 搜尋

網頁應具備搜尋功能，並提供搜尋輸入框。使用者應能搜尋標題或內容。當給定搜尋字串時，網頁應列出標題或內容中包含搜尋字串的頁面。

- 搜尋時可以使用 `/` 來定義多個關鍵字，網頁會以 **OR 邏輯**列出標題或內容中包含任一個關鍵字的頁面。
- **[新增]**：搜尋功能應支援**不分區大小寫**。當沒有搜尋結果時，應顯示「沒有找到相關文章」的提示訊息。
- 範例：當使用者輸入 `Taipei/Expo` 時，可以找到並且列出所有標題或內容中包含「Taipei」OR「taipei」OR「Expo」OR「expo」的頁面。

## 選手注意事項

- 網頁將可透過以下地址瀏覽：`https://webXX.web.tw/XX_module_c/`，其中 XX 是你的崗位號碼。
- 您可以將模組作答結果放在子資料夾或不同的 port 中。請從 `https://webXX.web.tw/XX_module_c/` 路徑重新導向至你的目標位置。
- 請注意，如果你使用 NodeJS，請了解 Windows（工作站）和 Linux（伺服器）上的 `node_modules` 檔案是不同的。使用錯誤的 `node_modules` 資料夾可能會導致預期外的錯誤。
- 如有必要，您可以提供 README 檔案來提供執行指引。
- 請考慮更好的**無障礙性**。將使用 aXe 無障礙開發工具進行整頁掃描。
- 請定義 `.gitignore` 檔案，以跳過一些暫存資料夾或建置資料夾。（請記得也一併將此 `.gitignore` 檔案上傳至伺服器）
- 此模組將使用 **Google Chrome** 瀏覽器進行評分。
